# Zfold UI / UX

> 视觉参考保留。入口、窗口和状态语义以 [PRODUCT_PLAN.md](../PRODUCT_PLAN.md) 为准；旧“主界面/悬浮面板”分开设计的描述不能作为保留两套聊天 UI 的依据。


原生 Android，优先围绕正在使用的 App 提供简洁、可打断的操作。保持 Pi 本地运行架构。

## 视觉

- 暖白底、墨色文字、陶土橙强调；夜间参照 Office 的中性深灰分层，仍只用少量橙色强调。参考 Office 的对话层级和输入布局，不引入其服务器或 Web 运行时。
- 颜色集中在 Ui.Theme；所有面板和设置使用同一套语义色。
- Android 系统中文字体，正文 15–16sp、辅助 11–13sp、品牌 16sp。
- 4/8dp 间距；悬浮面板仅顶部圆角 24dp、底部直角贴边，输入容器约 20dp，控件 14dp。
- 使用 Phosphor Regular 原始 SVG 转 Android VectorDrawable，统一 20–24dp 图形和至少 48dp 点击区域。
- 不使用 emoji 或字体字符作为操作图标。避免装饰性循环动画。

## 悬浮面板

- 标识与状态在同一紧凑头部；会话、最小化、关闭使用轻量图标动作。
- 截图缩略图与来源置于输入容器内，保留独立移除按钮；移除不应误触预览。
- 已发送的文字与选区缩略图留在消息卡片，重新打开后从最近历史恢复。
- 主界面与悬浮面板均由左侧滑出会话导航栏；显示当前会话、首条提问与时间，可新建或切换，切换后立即更新可见消息。遮罩、关闭按钮和返回键均可收起侧栏。
- 主要动作随状态变化：空输入禁用发送，有输入发送，执行中停止。
- 次级动作是说话、圈选；错误保留用户输入并提供重试或模型设置入口。
- 回复在原面板流式显示，可复制。只有用户仍在底部时自动跟随。
- 回复不是容器。主画布只有一个内容层；助手输出按排版阅读，不加白卡、边框和投影。只有输入/动作条这类可操作表面，以及单个工具证据卡才是容器。禁止把“回复卡 + 输入卡”变成两个大块。
- 输入操作面不用描边和投影强调；用表面色、圆角、间距和动作密度建立边界。会话入口使用侧边栏图标，侧边栏左侧滑出，遮罩和返回必须可用。
- 不设独立顶栏。品牌归属侧边栏；运行状态贴近输入操作面。低频系统入口进入侧边栏，不与内容争夺垂直空间。
- 状态不是常驻行。空闲输入面只有输入框和动作区；任务、识别、播报和错误反馈短暂出现，结束或超时后自动收起。
- 输入动作必须随容器宽度切换密度。折叠外屏隐藏动作文字并压缩为图标，发送永远完整保留在容器内；展开屏才允许图标 + 文字。不得让固定宽度动作把主操作挤出右缘。
- 已发消息像 Office 的人类气泡靠右，助手回复作为可阅读正文；附件、输入、说话、圈选和发送属于同一底部容器。
- 未配置模型必须有清楚的设置入口，不能让用户通过点击错误段落猜操作。
- 收起保留草稿和选区；关闭终止当前交互。状态用文字与图形同时表达。
- 开启系统减少动画时不播放入场、波形或循环动画。

## 主界面

- 顶部只保留品牌、实际状态和常用入口；模型名称等技术信息留在设置中。
- 消息流在折叠内屏居中、最大 720dp；用户消息靠右成气泡，助手头像/名称引导左侧正文，回复不铺满背景卡。
- 空会话在阅读区居中，给出一句用途和一个轻量示例。输入区固定在底部，先是文字与附件，再是说话、圈选和发送工具行；键盘出现时整体上移。
- 375dp 与 320dp 外屏保留主要动作；宽度变化时调整布局而不丢失未发送输入。

## 圈选

- 手绘闭合轮廓后先预览，再点“使用选区”；提供重新圈选和明确取消。
- 遮罩仅覆盖选区之外，选区保持原色。发送 PNG 时圈外透明，裁剪使用截图坐标，不拉伸截图。
- 工具栏避开系统栏，所有动作提供辅助功能名称。

## 验收

检查 Fold7 外屏、375dp 小屏、横屏、大字体和深色；检查键盘、截屏附件、执行状态、错误反馈、复制与收起。测试数据和模型 fixture 与手机真实配置隔离。

资料：apple-design、ui-ux-pro-max。数据库推荐的网页 Hero / 字体组合不适用于此原生助手，未采用；采用其可访问性、按压反馈和状态反馈原则。

- 贴底面板背景延伸至手势条区域；底部安全留白放在面板内部，键盘出现时贴齐键盘上沿。
